# Coding Quality Loop with DeepSeek Harness

Source-checked recipe for [DeepSeek Harness `0.2.1-rc.3` at `22ddee3`](https://github.com/deepseek-ai/deepseek-harness/tree/22ddee3792402c3e70ec5f86a63c3e3e895a2f60), which [requires Node >=24.9.0](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/package.json#L2-L9). It is an optional host recipe, not an install target or a CQL dependency. No live Harness session, provider, or model was run for this recipe.

## Inspect, reconcile, then resume

1. From the target project root, use a complete CQL source checkout and run `python3 /path/to/coding-quality-loop/scripts/quality_loop.py brief --cwd "$PWD" --json`. A skill-only copy does not install this Python CLI. Its `recovery` field compares raw source, index, record and allowlist bytes with a prior *local* passing verification; older markers without a bound record path and source snapshot report `unknown`. Matching bytes do not prove checks would still pass in the current environment. The brief does not run `verify`, execute a recorded command, inspect remote side effects, or certify the task done.
2. Inspect the persisted Harness session with a **read** handle: `await ctx.sessionPersistence.open(sessionId, 'read')`, then `await handle.read()` and `await handle.close()` in a `finally` block. Read mode takes no write ownership. The higher-level cold reader may add interrupted-turn closing events **in memory**, so use the raw read handle when exact stored events matter. [Persistence contract](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/session/session-persistence/src/handle.ts#L8-L13), [cold reader](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/session-query/session-query/src/cold-read.ts#L18-L53).
3. In the raw log, a `tool/call` with no matching `tool/result` has an unknown outcome; the [`TOOL_OUTCOME_UNKNOWN`](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/core/session/src/repair.ts#L13-L35) code appears when interrupted-turn closers are synthesized. The call may have acted before its result was saved. Inspect the target system or reconcile through a stable idempotency key; when neither is possible, stop for an owner decision. A CQL `blocked` evidence row alone is not proof that a user decision is required; use the record's `escalated` status and `escalation_reason` for that dependency.
4. Only after inspection, deliberately resume and run relevant checks. `ctx.agents.resume({ resumeSessionId })` claims a write handle and may append repair events; it is **not** a passive read. Restored `next-turn` or `next-step` inbox entries may run after a later wake, even though the restored agent initially appears idle. Recheck the current diff and any review attestation. CQL `verify` and `run-evidence` execute allowlisted commands, so never run them automatically during cold recovery. [Resume path](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/core/agent-loop/src/index.ts#L748-L807), [restored inbox](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/core/agent-loop/src/inbox.ts#L23-L51).

For a Harness-owned checkpoint, await `handle.flush()` after appending events **only if your code owns that write handle**. A live agent owns its handle internally; use `ctx.sessions.flush(agent.session)` or mount the standard checkpoint policy instead of opening a second writer. [`append` makes events accepted and visible; resolved `flush` is the backend-independent crash-durability barrier](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/session/session-persistence/src/handle.ts#L84-L109). A failed flush must block dependent dispatch. The standard policy flushes before model requests, top-level tools, and next steps. CQL's own atomic record replacement is not a Harness flush or a power-loss guarantee. [Checkpoint policy](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/session/session-checkpoint-policy/src/index.ts#L47-L78).
